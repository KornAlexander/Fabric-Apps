# dwg cli with Caldova Finance

dwg cli turns one JSON app spec into two targets: Fabric App pages (Rayfin, React) with the original byDatenWG
visuals, and the same report as a Power BI project (PBIP), with a parity test between them. Caldova Finance uses it
for the "Original visual" view of its three statements and for the Power BI twin "Caldova Finance (Power BI)".

Work from the template's root folder. Every command below runs there.

## Set up once

1. Clone dwg cli next to the template (or anywhere and set `DWG_CLI` to that folder), then run its installer:

   ```bash
   git clone https://github.com/Losveratos/dwg-cli ../dwg-cli
   node ../dwg-cli/install.mjs
   ```

   The installer installs packages, downloads Chromium (about 150 MB), copies dwg's own German skill `dwg` into
   `~/.claude/skills` and runs a self test. `--no-browser` and `--no-skill` skip the download and the home-folder
   write. An agent asks the person before running it.

2. Check: `npm run dwg -- doctor` and `npm run dwg:check` (expect "0 Probleme" / "0 Fehler"; dwg prints German).

`npm run dwg -- <command>` (tools/dwg.mjs) runs dwg with paths relative to the template; with no checkout it says
how to get one and exits 2. `npm run dwg -- --where` prints the checkout's folder; `<dwg-cli>` below stands for it.
The commands work the same in bash and PowerShell; only the `<dwg-cli>` placeholder needs filling in.

## What lives where

| Path | What it is | Edit? |
| --- | --- | --- |
| `dwg/caldova-finance.json` | The dwg spec: three pages, one tile each (T04B income statement, T05A balance sheet, T05B cash flow) bound to the English contract tables | Generated by `tools/make-dwg-spec.mjs`; change the generator, not the file |
| `tools/make-dwg-spec.mjs` | Builds the spec: bindings, titles, number format, colours (#5DBB2C good, #FF0000 bad); visual settings come from dwg's showcase | Yes |
| `src/dwg/`, `src/vendor/` | Generated by `dwg app page`: page specs, DAX, `DwgPage`, the built visuals | No, regenerate |
| `tools/dwg-english.mjs` | Patches the generated layer to English (dwg writes German UI strings) | Only when it reports a missing string |
| `src/domain/dwgPeriod.ts` | Slices the spec to the chosen year and months; builds every query the pages can send | Yes, for new periods or pages |
| `public/data/dwg-snapshot.json` | The answers to those queries, baked from the model | No, `npm run bake` |
| `fabric/caldova-finance.SemanticModel` | Direct Lake model with the dwg data contract (`Calendar`, `P&L/BS/CF Account`, `P&L/BS/CF Fact`) | Via `tools/contract_tmdl.py` |
| `fabric/caldova-finance.Report` | The Power BI twin, generated by `dwg pbip` | No, regenerate |

## Recipes

### Look up a template

```bash
npm run dwg -- templates --lang en            # all 30: ChartKitchen C01–C13, P&L T01A–T12H, T05A/T05B
npm run dwg -- templates T05A --lang en       # roles (required, recommended, optional) and settings
```

### Change a statement's original visual (template, levels, numbers, texts)

1. Edit the page in `tools/make-dwg-spec.mjs` (`PAGES`: `tpl`, `bindings`, `numbers`, `defaultLevel`, texts).
2. `node tools/make-dwg-spec.mjs <dwg-cli>`, then `npm run dwg:check`. Fix every problem it names; when a role is
   ambiguous, name the field (`--<role> <field>`), never guess.
3. Regenerate the app layer: `npm run dwg -- --pages`. It runs `dwg app page` into a throwaway skeleton in the
   system temp folder (dwg needs a Rayfin app with a `fabric-semanticmodel` connector, which this app deliberately
   does not ship, see Rules), copies `src/dwg` and `src/vendor` back, deletes the skeleton and runs
   `tools/dwg-english.mjs`. No Rayfin CLI and no Fabric sign-in needed. Do not generate into a copy of the template
   instead: a copy carries `rayfin/.deployments.json`, and with a connector a `rayfin up` there would redeploy the
   real app owner-only.

4. Re-bake the answers (needs the model: `FABRIC_PBI_TOKEN`, else an Azure CLI sign-in, `az login --tenant <id>`;
   the target ids in `tools/fabric/target.json`, see `target.example.json`): `npm run bake`, then
   `npm run bake:check` (the drift gate; it also counts the visual's queries).
5. `npm run lint`, `npm test`, `npm run build`, `npm run probe` (no scroll at 1366 and 1920 px, original visual drawn).

### Rebuild the Power BI twin from the same spec

```bash
npm run dwg -- pbip new --out fabric/caldova-finance.Report --name "Caldova Finance (Power BI)" --model fabric/caldova-finance.SemanticModel --template "<dwg-cli>/examples/showcase/ZlatyLev Showcase.Report"
npm run dwg -- pbip register --report fabric/caldova-finance.Report --pbiviz "<dwg-cli>/visuals/pbiviz/pnlByDatenWG.1.7.0.0.pbiviz"
npm run dwg -- pbip pages --report fabric/caldova-finance.Report --spec dwg/caldova-finance.json
npm run dwg -- validate fabric/caldova-finance.Report
```

Publishing it (`python tools/fabric/publish_report.py`) writes to a Fabric workspace: a person does that.

### Bring your own model

Shape it like the dwg data contract (`examples/showcase/CONTRACT.md` in dwg cli): an account table per
statement with `L1`, `L2`, `AccountID`, `Account`, `SortOrder`, `RowType`, `FormulaDef`, `SignConvention`,
`DisplayInvert`, `VarianceInvert`, and a fact table with AC/PY/PL/FC measures. `tools/contract_tables.py` and
`tools/contract_tmdl.py` show it for Caldova, `tools/fabric/verify_contract.py` proves the balance sheet balances,
closing cash ties and net income matches. Then point the bindings in `tools/make-dwg-spec.mjs` at your tables and
run the recipe above.

### Add a page from a template (beyond the three statements)

`npm run dwg -- tile add --spec dwg/caldova-finance.json --new-page "<Name>" --template <ID> --model fabric/caldova-finance.SemanticModel [--measure <stem>] [--dry-run]`.
The app only shows the three statement pages: a new page also needs a view in `src/components/OriginalStatement.tsx`,
a period slice in `src/domain/dwgPeriod.ts` (`DWG_PAGES`) and a re-bake, or it stays in the Power BI twin only.

## Rules

- Never ship the live `fabric-semanticmodel` connector in the deployed app: with it the app is owner-only (Rayfin
  1.36). The original visual answers its DAX from the baked snapshot; `npm run bake:check` must pass before a deploy.
- Do not edit `src/dwg/`, `src/vendor/` or `fabric/caldova-finance.Report` by hand; regenerate them.
- Agents do not deploy (`npx rayfin up`) or publish to Fabric; a person does, after the checks above.
- Credit stays as it is: the visuals and dwg cli are Michael Tenner's (Daten-WG), MIT, see `NOTICE`.
