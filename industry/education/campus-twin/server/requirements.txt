#
# ⚠️ Declared because `server/intake.py` imports it DIRECTLY, not because anything was missing at
# runtime: fastapi already drags it in, so this line changes nothing about what gets installed.
# It is here so the version that arrives is one somebody chose. A direct import satisfied only by
# somebody else's transitive dependency breaks on the day that dependency is relaxed, and the
# traceback then blames a file that was never edited.
pydantic>=2.7
#
# ⚠️ `pyodbc` INSTALLS CLEANLY AND CANNOT CONNECT YET, and that is deliberate rather than an
# oversight. The wheel needs `libodbc.so` at IMPORT time and a driver at CONNECT time, and
# `python:3.12-slim` carries neither. The Dockerfile change for that is NOT made here because
# there is no Docker daemon on this machine to verify an apt step, and an unverified Dockerfile
# edit breaks the next build for everybody.
#
# The container is safe in the meantime because `server/intake_store.py` imports pyodbc LAZILY,
# inside `_connect()`. Nothing imports it at start-up, `tools/tests/test_auth_degradation.py`
# proves the whole app still boots and serves with the module absent, and the intake routes answer
# 503 rather than crashing. To finish it, add to the Dockerfile before `pip install`:
#     apt-get update && apt-get install -y --no-install-recommends curl gnupg unixodbc
#     # then Microsoft's apt repo and: ACCEPT_EULA=Y apt-get install -y msodbcsql18
pyodbc>=5.1
